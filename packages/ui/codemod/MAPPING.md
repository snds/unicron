# Material Symbols → Carbon: the icon map

_Generated by `node packages/ui/codemod/sync.mjs` from [material-to-carbon.json](material-to-carbon.json). Edit the JSON, not this file._

323 Material names are mapped: 315 to 249 Carbon icons, 8 to nothing. Carbon names are the svg names in @carbon/icons 11.92.0 (Apache-2.0).

How each target was chosen: the Carbon icon with the same **meaning**. Where the Figma file or an app's spec already draws a place with a Carbon icon, that icon is used. When Carbon has no honest match, the name maps to nothing and the note says what to do. There are no sparkle icons.

"Where used" counts string literals in icon positions on 2026-11-13: `ui` and `playground` are this repo; Lockdown also counts the icon names its Rust templates carry.

## Run it

```bash
npx unicron-codemod icons apps/web/src --dry   # see what would change
npx unicron-codemod icons apps/web/src         # write it
```

It also turns `fill` on `<Icon>` and `<IconButton>` into the glyph's filled name where the curated set has one (`name={pinned ? "pin--filled" : "pin"}`), since `fill` often marked a state, and lists by line every `fill`, `weight`, `grade` and `opticalSize` it leaves. Those props are gone in 1.0, so the type checker names them too.

Run it **once**, on a clean tree, and read the diff. A second run would rename names that exist in both sets (`error` becomes `warning`, and `warning` would then become `warning--alt`), so the tool refuses when it finds Carbon names already in place.

## Names that arrive as data

The codemod rewrites names written in source, and `tsc` finds the rest of those. Neither reaches a name that arrives at run time: one a server sends, or one a person's saved template stores. Cast to `IconName`, it type-checks and draws an empty box marked `data-icon-missing`.

- **Names a server or a build step writes** (Lockdown's Rust templates, for one): change them at the source, with this map.
- **Names already stored** (a saved template, a synced setting): translate them once, when they are read, with `iconFromMaterial()` from `@unicron/ui`, then store the Carbon name. It returns the name from this map, or `null` for a name with no Carbon match and for anything that is not a Material name:

```ts
import { iconFromMaterial, isIconName } from "@unicron/ui"

const icon = iconFromMaterial(stored) ?? (isIconName(stored) ? stored : "document")
```

Translate only what was written before the switch. A name in both sets (see *Same word*) means the Material drawing in old data and the Carbon one in new data, so mark the stored data with a version, or translate it in one migration, rather than on every read.
